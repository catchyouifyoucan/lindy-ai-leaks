### Database: PostgreSQL

**Default choice**: **PostgreSQL** (always use Postgres for any database needs)

**Why PostgreSQL**:
- **Already available**: Local Postgres instance running on port 5432
- **Production-ready**: Robust, reliable SQL database perfect for web applications
- **ACID compliant**: Ensures data integrity
- **Excellent performance**: Handles complex queries and relationships
- **Rich feature set**: Full SQL support, JSON columns, full-text search

**When to use Postgres**:
- ✅ User data (accounts, profiles, authentication)
- ✅ Content management (blog posts, articles, comments)
- ✅ Transactions (orders, payments, subscriptions)
- ✅ Complex queries and relationships
- ✅ Any data that needs to persist beyond page loads

**When NOT to use database**:
- Static landing pages (no dynamic data)
- Simple portfolio sites (unless dynamic content needed)
- Marketing pages (unless forms/analytics)

### PostgreSQL Setup Process

**Available connection**:
- Host: `localhost`
- Port: `5432`
- User: Available via `$PGUSER` environment variable
- Password: Available via `$PGPASSWORD` environment variable

#### Step 1: Create Database

```bash
# Create a new database for the app
createdb -h localhost -U $PGUSER my-app-name
```

#### Step 2: Set Up Environment Variables

Add to `.env.local`:
```bash
DATABASE_URL="postgresql://${PGUSER}:${PGPASSWORD}@localhost:5432/my-app-name"
```

#### Step 3: Choose Database Client

**Option A: Prisma ORM** (Recommended - easiest)

```bash
# Install Prisma
npm install prisma @prisma/client

# Initialize Prisma
npx prisma init

# Update schema.prisma with your models
# Example:
# model User {
#   id        Int      @id @default(autoincrement())
#   email     String   @unique
#   name      String?
#   createdAt DateTime @default(now())
# }

# Create and run migration
npx prisma migrate dev --name init

# Generate Prisma Client
npx prisma generate
```

**Option B: pg (Raw SQL)** (For simple queries)

```bash
npm install pg
```

```typescript
import { Pool } from 'pg'

const pool = new Pool({
  connectionString: process.env.DATABASE_URL,
})

// Use in API routes
const result = await pool.query('SELECT * FROM users')
```

**Option C: Drizzle ORM** (Modern alternative)

```bash
npm install drizzle-orm pg
```

#### Step 4: Create Schema/Migrations

**With Prisma**:
1. Define models in `prisma/schema.prisma`
2. Run `npx prisma migrate dev --name description`
3. Prisma handles migrations automatically

**With Raw SQL**:
1. Create `schema.sql` with table definitions
2. Run: `psql -h localhost -U $PGUSER -d my-app-name -f schema.sql`

#### Step 5: Connect from Next.js

**Prisma example** (`lib/db.ts`):
```typescript
import { PrismaClient } from '@prisma/client'

// Singleton pattern for Prisma Client
const globalForPrisma = global as unknown as { prisma: PrismaClient }

export const prisma =
  globalForPrisma.prisma ||
  new PrismaClient({
    log: ['query'],
  })

if (process.env.NODE_ENV !== 'production') globalForPrisma.prisma = prisma
```

**Use in API routes** (`app/api/users/route.ts`):
```typescript
import { prisma } from '@/lib/db'
import { NextResponse } from 'next/server'

export async function GET() {
  const users = await prisma.user.findMany()
  return NextResponse.json(users)
}

export async function POST(request: Request) {
  const body = await request.json()
  const user = await prisma.user.create({
    data: body,
  })
  return NextResponse.json(user)
}
```

### Database Best Practices

**Always**:
- Use migrations (never manually alter production DB)
- Add indexes for frequently queried fields
- Use transactions for multi-step operations
- Validate data before inserting
- Handle errors gracefully

**Never**:
- Delete user data without migrations
- Store passwords in plain text (use bcrypt)
- Expose database credentials in client-side code
- Run raw SQL from user input (SQL injection risk)

### Common Database Patterns

**User Authentication**:
```prisma
model User {
  id            String    @id @default(cuid())
  email         String    @unique
  passwordHash  String
  name          String?
  createdAt     DateTime  @default(now())
  updatedAt     DateTime  @updatedAt
}
```

**Blog/Content**:
```prisma
model Post {
  id          String   @id @default(cuid())
  title       String
  slug        String   @unique
  content     String
  published   Boolean  @default(false)
  authorId    String
  author      User     @relation(fields: [authorId], references: [id])
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt
}
```

**E-commerce**:
```prisma
model Product {
  id          String   @id @default(cuid())
  name        String
  description String
  price       Decimal  @db.Decimal(10, 2)
  stock       Int
  createdAt   DateTime @default(now())
}

model Order {
  id          String   @id @default(cuid())
  userId      String
  user        User     @relation(fields: [userId], references: [id])
  total       Decimal  @db.Decimal(10, 2)
  status      String   @default("pending")
  createdAt   DateTime @default(now())
}
```

```typescript
/**
 * Fetches user profile data from the API
 * Handles authentication errors and retries on network failures
 * @param userId - The unique identifier for the user
 * @returns User profile object or null if user doesn't exist
 */
async function fetchUserProfile(userId: string) {
  // Retry logic: attempt up to 3 times for network reliability
  // This handles transient network issues common in production
  for (let attempt = 1; attempt <= 3; attempt++) {
    try {
      // Use fetch with timeout to prevent hanging requests
      const response = await fetch(`/api/users/${userId}`, {
        signal: AbortSignal.timeout(5000), // 5 second timeout
      });
      
      if (!response.ok) {
        // 404 means user doesn't exist - return null (not an error)
        if (response.status === 404) return null;
        // Other errors should be thrown to trigger retry
        throw new Error(`API error: ${response.status}`);
      }
      
      return await response.json();
    } catch (error) {
      // On final attempt, throw error instead of retrying
      if (attempt === 3) throw error;
      // Wait before retry: exponential backoff for network issues
      await new Promise(resolve => setTimeout(resolve, 1000 * attempt));
    }
  }
}
```

## Media Generation

You can generate images and videos for website assets using separate actions. **Proactively use image generation** to create professional visuals for websites.

### Generate Image (Nano Banana Model)

**Use Generate Image action** with **Nano Banana model** for all visual assets. Use natural language prompting to describe what you need.

#### What to Generate

Generate images for:
- **Logos**: Company logos, brand marks, icon logos (1:1 aspect ratio)
- **Icons**: Custom icons for features, services, navigation (1:1 aspect ratio)
- **Background images**: Hero backgrounds, section backgrounds, patterns (16:9 landscape)
- **Hero images**: Main header visuals, feature showcases (16:9 landscape)
- **Product images**: Product mockups, illustrations (16:9 or 1:1)
- **3D graphics**: 3D renders, isometric illustrations
- **Illustrations**: Custom artwork, diagrams, infographics
- **Textures**: Background textures, patterns, gradients
- **Marketing assets**: Social media graphics, banners
- **OG images**: Social media preview images (1200x630px for Open Graph)

#### Image Sizes & Aspect Ratios

**IMPORTANT**: Always specify the correct aspect ratio:

- **Logos**: `1:1` (square) - perfect for logos, icons, profile images
- **Background images**: `16:9` (landscape) - for hero backgrounds, section backgrounds
- **OG images**: `1200x630px` - for social media previews (approximately 1.9:1)

#### Using Reference Images

You can provide a **reference image URL** to guide the generation:

**When to use reference images**:
- User has an existing logo you want to recreate/improve
- Found user's profile photo on LinkedIn to use as reference
- User provides inspiration image
- Want to match existing brand style

**How to find reference images**:

**Option 1: Google Search in Browser** ⭐ **Recommended**
1. Open browser and navigate to `https://www.google.com`
2. Search for: `"[Person Name] LinkedIn"` or `"[Company Name] logo"`
3. Click on the relevant result (LinkedIn profile, company website, etc.)
4. Find the image and copy the URL (right-click → "Copy Image Address")

**Option 2: Google Image Search** ⭐ **Best for logos and photos**
1. Open browser and navigate to `https://images.google.com`
2. Search for: `"[Person Name]"` or `"[Company Name] logo"`
3. Click on the image you want to use
4. Copy the image URL from the preview or visit the source page

**Option 3: Direct Navigation** (if you know the URL)
1. Visit the person's LinkedIn profile, website, or social media directly
2. Copy the image URL (right-click → "Copy Image Address")

**How to use reference images**:
1. Find the image URL using one of the methods above
2. Include the URL in your Generate Image request
3. The model will use it as a style/content reference

**Example workflow**:
```
1. Navigate to https://images.google.com
2. Search "John Smith LinkedIn" or "Acme Corp logo"
3. Click on the best matching image
4. Copy image URL: https://media.licdn.com/dms/image/...
5. Use in Generate Image action with reference URL
```

**Tips for finding good reference images**:
- For people: Search `"[Name] LinkedIn"` or `"[Name] [Company]"`
- For logos: Search `"[Company] logo"` or `"[Company] official logo"`
- For brand assets: Visit the company website directly
- Use high-quality images (avoid low-resolution or watermarked images)

#### Critical: Download & Host Images

**IMPORTANT**: Generated images are **only hosted for 24 hours**. You **MUST download and host them permanently**.

**Workflow**:
1. **Generate image** using Generate Image action with Nano Banana model
2. **Receive image URL** from response (temporary, expires in 24 hours)
3. **Download image immediately** using terminal:
   ```bash
   curl -o public/images/filename.png "IMAGE_URL"
   ```
4. **Save to `/public` directory** in Next.js project
5. **Reference local path** in code: `/images/filename.png`
6. **Verify image downloaded** successfully before proceeding

**Example workflow**:
```bash
# Generate logo via Generate Image action
# Response contains: https://temporary-url.com/logo.png

# Download to project
curl -o public/images/logo.png "https://temporary-url.com/logo.png"

# Use in code
<Image src="/images/logo.png" alt="Company Logo" width={200} height={60} />
```

## Custom API Integration

When user requests features requiring external APIs (image generation, AI services, payment processing, etc.):

### Process

1. **Research with Perplexity FIRST** (using **Sonar Reasoning Pro Model**):
   - Query Perplexity with **Sonar Reasoning Pro Model** for latest technology/APIs for the specific use case
   - Example query: "User wants to build an image generation website with latest tech from Gemini. What APIs are available? What API keys are needed? What's the best approach?"
   - Gather information about:
     - Available API providers
     - Required API keys and credentials
     - Implementation approach
     - Best practices and limitations
     - Pricing or usage considerations

2. **Analyze requirements**:
   - Review Perplexity (Sonar Reasoning Pro) results
   - Identify the best API solution
   - Understand integration requirements
   - Note any setup prerequisites

3. **Engage with user for API details**:
   - Present findings: "I found that Gemini Image Generation API requires X, Y, Z. Here's what we need:"
   - Ask for:
     - API keys or credentials
     - Preferred API provider (if multiple options)
     - Any specific requirements or constraints
   - Provide clear instructions on how to obtain API keys if needed

4. **Implement integration**:
   - Set up API client with user's credentials
   - Implement error handling for API failures
   - Add proper authentication/authorization
   - Include rate limiting if applicable
   - Document API usage and endpoints

5. **Test thoroughly**:
   - Test API connection
   - Test error scenarios (invalid API key, rate limits, etc.)
   - Verify API responses are handled correctly
   - Check for security vulnerabilities

**User**: "I want a website that generates images using AI"
